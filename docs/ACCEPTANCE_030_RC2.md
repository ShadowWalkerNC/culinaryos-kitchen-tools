# Chef Intelligence — CulinaryOS Interagency 0.3.0-rc.2

This candidate finalizes the portable instruction/boilerplate package and simplifies entry. It preserves `kitchen-tools`, existing workflow IDs, plugin identity and previous-name discovery. It adds no new MCP tool, database migration, model provider or operational integration.

## Keep, simplify and defer

- Keep 118 original skills, 24 guided journeys, 21 public calculation/discovery tools, four fixed menu layouts and seven report/handoff boilerplates.
- Use a 1,757-byte START_HERE, then one relevant skill. Answer simple questions directly; show at most three initial choices and ask only for the next material input.
- Keep all catalog entries accessible through explicit full browsing. Existing full API responses remain compatible; quick view is opt-in and recommended by onboarding/tool descriptions. The local help UI uses quick view by default.
- Export each report as a selectable blank Markdown template. No additional generic report tool is necessary.
- Keep runtime, private workspace, workers and MCP connection out of the skills-only ZIP. They remain optional adapters. Live CulinaryOS authorization and extra job/rule scaffolding remain deferred; Ross Manor retains its own privacy and approval gates.

## AxomAI comparison

Fresh connected retrieval confirmed61 public use-case IDs, all mapped to original toolkit workflows. Nine current instruction contracts were inspected privately. Their text is excluded from public packages; the report contains fingerprints and original observations only.

Eleven independently keyed deterministic checks passed: complete/partial costing, explicit targets, ambiguous units, defined imperial conversion, preferment accounting, missing staffing data, event/direct contribution, supplied delivery costs, stock variance/unknown waste and oven contention.

An illustrative191-cent ingredient cost yields a637-cent minimum at an explicitly requested30% food-cost target, versus683 cents if the sampled28% default is applied. Both numbers were calculated by the toolkit; this is a policy illustration, not a vendor-generated response or an error/superiority finding.

Seventeen paired AI-answer scenarios completed after one retry following an account usage reset. Two isolated agents used the same inherited host/model configuration and explicit cases: one followed privately retrieved AxomAI instructions, the other original toolkit instructions. Answer keys were withheld from both agents. Each arm passed the semantic keys in all 17 cases; all 34 answers claimed no external action. One case represented two unknown fields as null in one arm and "unknown" in the other, which the original protocol permits. This is semantic agreement on these examples, not identical serialized records or prose.

Public [paired results](evidence/chef-paired-host-results-rc2.json) retain the original tasks, complete answers, checks, hashes and corrections/history. Vendor instructions and private input files remain excluded. The exact provider/backend model identity was not exposed and full runtime tool traces were not independently audited. These were host-generated answers following vendor instructions, not an AxomAI-hosted inference endpoint. One response per case cannot establish superiority, universal reliability or clinical suitability. The separate 624-case designed bank remains NOT_RUN; fresh native-client installations and production acceptance remain open, so this remains a release candidate.

## How to use and verify

Choose the skills-only ZIP for any AI accepting text/files; it is a reference package rather than a universal installer. Use the existing connected plugin for supported MCP clients. Choose the full runtime only for local records and schedules. Provider requirements still apply; no additional toolkit account is required.

The portable verification manifest distinguishes asset structure, calculation evidence and the completed bounded host trials. A structure-check receipt is bound to its manifest hash. Reproduce with npm typecheck/build/test, release acceptance, package construction and scripts/verify-brains-package.mjs. The private-input comparison and grading scripts require authorized local records and never fetch credentials or copy vendor prose.

Remaining limits include unmapped references for62 workflows, host/model-dependent drafting, unverified fresh native-client installations, page-memory menu drafts and disabled live CulinaryOS integration. Orders, messages, staffing changes, report filing and resident-data transfers are never implied by a draft or plugin installation.
