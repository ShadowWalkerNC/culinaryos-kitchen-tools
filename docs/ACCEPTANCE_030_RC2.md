# Chef Intelligence — CulinaryOS Interagency 0.3.0-rc.2

This candidate finalizes the portable instruction/boilerplate package and simplifies entry. It preserves `kitchen-tools`, existing workflow IDs, plugin identity and previous-name discovery. It adds no new MCP tool, database migration, model provider or operational integration.

## Keep, simplify and defer

- Keep 118 original skills, 24 guided journeys, 21 public calculation/discovery tools, four fixed menu layouts and seven report/handoff boilerplates.
- Use a 1,757-byte START_HERE, then one relevant skill. Answer simple questions directly; show at most three initial choices and ask only for the next material input.
- Keep all catalog entries accessible through explicit full browsing. Existing full API responses remain compatible; quick view is opt-in and recommended by onboarding/tool descriptions. The local help UI uses quick view by default.
- Export each report as a selectable blank Markdown template. No additional generic report tool is necessary.
- Keep runtime, private workspace, workers and MCP connection out of the skills-only ZIP. They remain optional adapters. Live CulinaryOS authorization and extra job/rule scaffolding remain deferred; Ross Manor retains its own privacy and approval gates.

## How to use and verify

Choose the skills-only ZIP for any AI accepting text/files; it is a reference package rather than a universal installer. Use the existing connected plugin for supported MCP clients. Choose the full runtime only for local records and schedules. Provider requirements still apply; no additional toolkit account is required.

The portable verification manifest distinguishes asset structure, calculation evidence and blocked host trials. A structure-check receipt is bound to its manifest hash. Reproduce with npm typecheck/build/test, release acceptance, package construction and scripts/verify-brains-package.mjs. The private-input comparison script requires authorized local snapshots and never fetches credentials or copies vendor prose.

Remaining limits include unmapped references for62 workflows, host/model-dependent drafting, unverified fresh native-client installations, page-memory menu drafts and disabled live CulinaryOS integration. Orders, messages, staffing changes, report filing and resident-data transfers are never implied by a draft or plugin installation.
