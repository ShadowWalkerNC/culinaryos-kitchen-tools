# 0.3.0-rc.4 — library icon correction

The saved plugin had no logo or composerIcon fields in either its root manifest or retained Codex compatibility manifest, and no icon asset was bundled. This correction uses the existing CulinaryOS 128×128 SVG brand icon, with explicit contained relative paths in both manifests. It preserves the kitchen-tools identity, prompts, skills, connections, author and audience.

Packaging now includes the compatibility manifest and referenced asset in full and remote packages. The new branding check verifies synchronized presentation, contained asset paths, square dimensions, size and absence of external images/scripts. The publication receipt records actual checks and saved-source readback. A saved icon declaration does not by itself establish that an already-open client refreshed its cached library tile.

All 118 skill texts and calculator behavior are unchanged. Prior host comparisons retain their original versions. Native client execution across all platforms, the separate 624 designed cases, live CulinaryOS API integration and directory approval remain outside this icon correction.
